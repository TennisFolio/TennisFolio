# Feature: 클럽원 일괄 등록

## 1. Goal

클럽 관리자가 엑셀 또는 구글 스프레드시트의 클럽원 명단을 붙여넣어 여러 명을 한 번에 등록한다. 입력 오류와 중복 이름은 저장 전에 확인하며, 잘못된 일부 데이터 때문에 부분 등록이 발생하지 않도록 한다.

## 2. User Flow

```text
클럽 관리자: 일괄 등록 화면 진입
-> 표에 직접 입력하거나 시트에서 복사한 행을 붙여넣음
-> 입력 내용 확인
-> 필수값, 등급, 중복 이름 검증 결과 확인
-> 오류 없음: 전체 클럽원 등록
-> 오류 있음: 해당 행 수정 또는 삭제 후 다시 확인
```

## 3. Spec

- 기존 단건 클럽원 추가 화면에서 `한 명 추가`와 `일괄 추가` 중 선택할 수 있다.
- 일괄 등록 화면은 PC에서 최대 1200px 폭의 표를 표시하고, 720px 이하에서는 현재 클럽 화면과 같은 모바일 레이아웃으로 전환한다.
- 입력 표 열 순서는 `이름`, `성별(남/여)`, `역할(관리자/클럽원)`, `스킬 등급`, `비고`, `연락 메모`다.
- 이름과 성별은 필수다. 새 행의 성별 기본값은 `남`, 역할 기본값은 `클럽원`, 등급 기본값은 `미정`이다.
- 성별 드롭다운은 `남`, `여`만 제공하며 서버에는 각각 `MALE`, `FEMALE`로 전달한다.
- 역할 드롭다운은 `관리자`, `클럽원`만 제공한다. 붙여넣기 값이 정확히 `관리자`가 아니면 `클럽원`으로 변환한다.
- 스킬 등급 드롭다운은 해당 Club이 설정한 유효한 등급만 표시한다. 클럽에 등급이 없으면 `미정`만 표시한다.
- 붙여넣기는 행 단위 줄바꿈과 열 단위 탭을 사용한다. 순서는 표 열 순서와 동일하며, 성별은 `남/여`, 역할은 `관리자`만 관리자로 변환한다.
- 붙여넣기 단계에서는 중복 이름을 막지 않는다. `입력 내용 확인` 단계에서 입력 행끼리의 중복과 기존 활성 클럽원 이름 중복을 행별로 표시한다.
- 중복, 필수값 누락, 유효하지 않은 등급이 하나라도 있으면 전체 등록 버튼을 비활성화한다.
- 등록 API는 `POST /api/clubs/{clubPublicId}/members/bulk`이며 `members` 배열을 받는다. 관리자만 호출할 수 있다.
- 서버는 요청 전체를 검증한 후 하나라도 실패하면 저장하지 않는다. 모든 행이 유효할 때만 트랜잭션으로 전원을 저장한다.
- 이름 중복 기준은 현재 정책과 동일하게 같은 Club의 활성 클럽원 이름이다. 성별이 달라도 중복으로 본다.
- 단건 추가 API와 기존 단건 등록 화면은 유지한다.
- 화면 목업은 `docs/features/club/club-member-bulk-add-mockup.html`을 기준으로 한다.

## 4. Design Review

### Responsibility

- Controller / API: 일괄 등록 요청을 받고 인증 사용자 ID와 함께 command service에 전달한다.
- Service / Application: 관리자 권한 확인, 전체 요청의 이름·성별·역할·등급 검증, 배치 저장을 순서대로 수행한다.
- Domain: 기존 `ClubMember`, `ClubMemberRole`, `ClubSkillTier`를 그대로 사용한다.
- Repository / Persistence: 기존 활성 클럽원 이름 조회 규칙을 배치 검증에 재사용하고, 모든 검증 통과 뒤 저장한다.
- Frontend / UI: 표 편집, TSV 붙여넣기, 미리보기, 행별 오류, 등록 완료 후 클럽원 목록 이동을 담당한다.

### Review Questions

- 붙여넣기는 입력 편의 기능일 뿐, 저장 규칙의 최종 판단은 서버가 담당한다.
- 프런트엔드 검증과 서버 검증은 같은 이름 중복·등급 유효성 규칙을 공유한다.
- 전체 저장은 부분 성공을 허용하지 않아 운영자가 등록 결과를 예측할 수 있다.
- CSV/엑셀 파일 업로드, 사용자 계정 연결, 대규모 비동기 import는 현재 범위에 포함하지 않는다.

## 5. Plan / Commit Units

- [ ] `feat: add atomic club member bulk registration API`
  - 구현: 배치 request DTO, Controller endpoint, 전체 검증·저장 service flow를 추가한다.
  - 테스트 설명: 관리자 성공, 비관리자 거부, 입력 내 중복, 기존 활성 클럽원 중복, 잘못된 등급, 한 행 실패 시 전체 미저장을 검증한다.
  - 검증 기준: 관련 Club service/controller Java 테스트를 실행한다.

- [ ] `feat: add club member bulk registration screen`
  - 구현: 일괄 등록 라우트·표 편집·TSV 붙여넣기·등급 드롭다운·내용 확인·등록 요청을 추가한다.
  - 테스트 설명: 프런트엔드 테스트 코드는 작성하지 않는다. PC와 모바일에서 직접 입력, 붙여넣기, 오류 표시, 등록 성공을 수동 확인한다.
  - 검증 기준: 프런트엔드 테스트·빌드는 사용자 요청이 있을 때만 실행한다.

- [ ] `fix: align duplicate-name validation between preview and registration`
  - 구현: 서버 응답을 행별 오류로 표시하고, 동시 등록으로 인한 중복 실패도 수정 가능한 상태로 유지한다.
  - 테스트 설명: 미리보기 이후 같은 이름이 등록된 경우 저장 거부와 오류 안내를 검증한다.
  - 검증 기준: 관련 Java 테스트와 수동 오류 흐름을 확인한다.

커밋은 사용자의 별도 요청이 있을 때만 준비한다.

## 6. Development Validation

- [ ] 관리자가 여러 클럽원을 한 요청으로 등록할 수 있다.
- [ ] 시트의 탭·줄바꿈 데이터를 표 행과 열로 정확히 변환한다.
- [ ] 역할의 빈 값 또는 알 수 없는 값은 클럽원으로 등록된다.
- [ ] 유효하지 않은 성별, 중복 이름, 존재하지 않는 등급은 저장 전에 안내된다.
- [ ] 오류가 하나라도 있으면 아무 클럽원도 저장되지 않는다.
- [ ] 기존 단건 클럽원 등록이 유지된다.
- [ ] 프런트엔드 테스트·빌드는 사용자 요청이 없으므로 실행하지 않는다.

## 7. Final QA Checklist

- [ ] 관리자가 시트 명단을 붙여넣고 오류를 수정한 뒤 전체 등록을 완료할 수 있다.
- [ ] 모바일에서도 표 입력과 오류 확인이 가능하다.
- [ ] 등록 뒤 클럽원 목록에서 추가된 인원이 확인된다.
- [ ] 중복 이름이 기존 데이터나 같은 입력 안에 있어도 부분 등록이 발생하지 않는다.
